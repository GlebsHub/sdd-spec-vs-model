# Стенд: спека × модель × контур проверок

Стенд проверяет гипотезу: качество и стоимость результата агента зависят от полноты спецификации и от контура автоматических проверок. Переменные: модель (Haiku, Sonnet), спека (`spec/clients-table-brief.md`, `spec/clients-table-full.md`), контур проверок (есть / нет). Задача для агента — раздел «Мои клиенты».

Этот файл — правила для нас, когда строим стенд. Правила для оцениваемого агента — `base/CLAUDE.md` и `base/conventions.md`.

## Структура

| Путь | Что это |
|---|---|
| `base/` | Базовый проект без фичи «Мои клиенты». Харнесс копирует его во временную папку вне репозитория и кладёт туда одну версию спеки как `SPEC.md` |
| `base/CLAUDE.md`, `base/conventions.md` | Правила для оцениваемого агента |
| `spec/` | Обе версии спеки и `CHANGELOG.md` с историей полной версии |
| `eval/lib/make-copy.mjs` | Копия `base/` из git-коммита во временную папку вне репозитория, со спекой как `SPEC.md`, клоном `node_modules` и git-репозиторием «base» для диффа |
| `eval/lib/protected.mjs` | Защищённые пути в машиночитаемом виде |
| `eval/reference/` | Эталон: `files/` — только файлы фичи поверх базы, `build.mjs` — сборка копии с ними (`--bare` — без них) |
| `eval/acceptance/` | Скрытая приёмка AC-01…AC-15 и раннер `run.mjs`, см. `eval/acceptance/README.md` |
| `eval/harness/` | Харнесс прогонов, см. `eval/harness/README.md` |
| `eval/results/` | Результаты прогонов и сводка `summary.md` |
| `docs/` | Методика, изменения приёмки, журнал сборки (`build-log.md`, раньше `plan.md`), график результатов |

## Правила для `base/`

- **База заморожена на `541a56ff5977f131027cbcab71059da0ad1fcb21`.** Любое изменение `base/` после начала прогонов — только с подтверждения владельца стенда. После такого изменения все прогоны на прежней версии базы считаются несравнимыми с новыми: сравнивать можно только прогоны с одинаковым `baseCommit`.

- В `base/` только инфраструктура. Фичу «Мои клиенты» не реализуем ни частично, ни в виде примера.
- В `base/` нет ничего, что напрямую закрывает критерии приёмки: `staleTime` 60 с, scroll restoration, `validateSearch` для `/clients`, хуки клиентов, таблица, настройки колонок. Это делает агент. Базовый проект одинаков для всех прогонов и не подсказывает решение.
- Сценарии мок-бэкенда описаны только в `base/src/mocks/scenarios.ts`, не в `base/CLAUDE.md`: при краткой спеке агент не должен получать список состояний готовым.
- Перед коммитом в `base/` нужно, чтобы проходили `npm run check` и `npm run test:e2e`.

## Варианты контура проверок

- **С контуром:** `base/CLAUDE.md` как есть. Агенту разрешены `npm run check` и `npm run test:e2e`, готовность = оба зелёные.
- **Без контура:** харнесс вырезает из `base/CLAUDE.md` блок между `<!-- contour:start -->` и `<!-- contour:end -->`. Больше команды проверок нигде в инструкциях агента не упоминаются: `conventions.md` отсылает к `CLAUDE.md` за критерием готовности.

## Защищённые файлы

Список — раздел «Защищённые файлы» в `base/CLAUDE.md`, его машиночитаемая копия — `eval/lib/protected.mjs`; меняем оба вместе. Харнесс считает контрольные суммы этих файлов до и после прогона. Любое расхождение = провал прогона.

## Эталон и приёмка

- **Приёмка заморожена** с 23.10.2026, коммит `acb4071` и следующий за ним. Любое изменение `eval/acceptance/` — только с подтверждения владельца стенда. После такого изменения все завершённые прогоны (`eval/results/<config>/<run>/`) переоцениваются через `eval/harness/rescore.mjs` с `--reason`, а прежний результат остаётся в `acceptanceHistory`.
- Пилоты (`eval/results/_pilot/`) в сводку не входят; в отчёте идут отдельно.

- Эталон собирается только из `eval/reference/files/` поверх закоммиченной базы; в `base/` его не кладём. После любого изменения базы или эталона: `node eval/reference/build.mjs`, в копии `npm run check` и `npm run test:e2e`, затем `node eval/acceptance/run.mjs <копия> --repeat 3` — 15/15 без флаков.
- Приёмка на голой базе (`build.mjs --bare`) должна быть 0/15. Тест, который проходит без фичи, бесполезен.
- Тесты приёмки опираются только на спеку и контракт стенда (мок, `window.__mocks`); правила — в `eval/acceptance/README.md`.

## Результаты прогона

Кроме контрольных сумм защищённых файлов харнесс сохраняет в результатах прогона:

- `PLAN.md` агента;
- дифф `src/shared/api/queryClient.ts` относительно базы. Файл не защищён, так как conventions требуют задавать `staleTime` и `gcTime` в `queryClient`. Дифф показывает, как агент настроил свежесть и повторы;
- хэш коммита базы, из которой сделана копия.

## Версии зависимостей

Версии зафиксированы точно, без `^` и `~`, `package-lock.json` в репозитории. Проверены 22.10.2026.

- **TanStack Table 8.21.3, а не 9.x.** Версия 9.0 вышла 04.08.2026 с новым API. Модели в основном знают API v8. На свежем мажоре результат зависел бы ещё и от знания модели о новой версии, и эта переменная смешалась бы с переменными гипотезы.
- **MSW 2.x (2.15.0), а не 3.x.** Та же причина: 3.0 вышла 28.09.2026.
- **TypeScript 6.0.3, а не 7.x.** `typescript-eslint` 8.72 поддерживает TypeScript `<6.1`. Линтер с проверкой типов обязателен по `conventions.md`.

Остальное — последние стабильные версии на дату проверки.
