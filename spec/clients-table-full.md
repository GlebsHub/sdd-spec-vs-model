# Системный анализ. Раздел «Мои клиенты» (кабинет агента)

| Параметр | Значение |
|---|---|
| Продукт | Агентский кабинет |
| Портал | Портал агента |
| Раздел | Мои клиенты |
| Роль | Агент (прошёл онбординг, договор подписан) |
| Версия документа | 1.3 |
| Статус документа | Готов к разработке |
| Связанные страницы | Карточка клиента `/clients/:clientId` (вне рамок данного документа) |

## 1. Назначение

Раздел позволяет агенту видеть клиентов, привлечённых по его реферальной ссылке, отслеживать их статус и начисленную комиссию, находить нужного клиента и переходить в его карточку.

## 2. Термины

| Термин | Определение |
|---|---|
| Клиент | Физическое лицо, зарегистрировавшееся по реферальной ссылке агента |
| Статус клиента | Этап воронки привлечения (см. п. 4.2) |
| Комиссия | Сумма вознаграждения агента по клиенту за всё время. Передаётся в копейках целым числом |

## 3. Интеграция

### 3.1. Получение списка клиентов

`GET /api/agent/clients`

Контракт ответа задан Zod-схемой в слое `shared/api`. Ответ сервера проверяется схемой при получении, типы на фронтенде выводятся из схемы.

**Параметры запроса**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `cursor` | string | нет | Курсор следующей порции. Отсутствует для первой порции |
| `limit` | integer | да | Размер порции. Всегда `50` |
| `q` | string | нет | Поиск по ФИО, от 2 символов |
| `status` | string[] | нет | Фильтр по статусам, через запятую |
| `dateFrom` | string (date) | нет | Дата регистрации с, включительно, `YYYY-MM-DD` |
| `dateTo` | string (date) | нет | Дата регистрации по, включительно, `YYYY-MM-DD` |
| `sort` | string | нет | `поле:направление`. Поля: `registeredAt`, `fullName`, `commissionKopecks`. Направления: `asc`, `desc`. По умолчанию `registeredAt:desc` |

**Ответ 200**

| Поле | Тип | Описание |
|---|---|---|
| `items` | Client[] | Порция клиентов |
| `nextCursor` | string \| null | Курсор следующей порции, `null` если данных больше нет |
| `total` | integer | Общее количество клиентов с учётом фильтров |

**Client**

| Поле | Тип | Описание |
|---|---|---|
| `id` | string (uuid) | Идентификатор клиента |
| `fullName` | string | ФИО |
| `phoneMasked` | string | Телефон, уже замаскированный бэкендом, например `+7 *** ***-45-12` |
| `status` | enum | `LEAD`, `ACCOUNT_OPENED`, `FUNDED`, `INACTIVE` |
| `registeredAt` | string (date-time) | Дата и время регистрации, ISO 8601, UTC |
| `commissionKopecks` | integer | Комиссия агента в копейках, ≥ 0 |
| `productsCount` | integer | Количество подключённых продуктов, ≥ 0 |

**Ошибки**

| Код | Поведение |
|---|---|
| 401 | Глобальный обработчик приложения (вне рамок раздела) |
| 403 | Состояние «Нет доступа» (п. 7) |
| 5xx, сетевая ошибка, ответ не соответствует схеме | Состояние ошибки (п. 7) |

## 4. Состав экрана

Сверху вниз: заголовок «Мои клиенты» со счётчиком `total`, панель фильтров, кнопка «Настроить колонки», таблица.

### 4.1. Колонки таблицы

Порядок колонок фиксированный.

| № | Колонка | Поле | Формат отображения | Сортировка | Видима по умолчанию |
|---|---|---|---|---|---|
| 1 | ФИО | `fullName` | Как есть | да | да, нельзя скрыть |
| 2 | Телефон | `phoneMasked` | Как есть, без изменений | нет | да |
| 3 | Статус | `status` | Тег с текстом и цветом (п. 4.2) | нет | да |
| 4 | Дата регистрации | `registeredAt` | `ДД.ММ.ГГГГ` в часовом поясе пользователя | да | да |
| 5 | Комиссия | `commissionKopecks` | Денежный формат (п. 4.3) | да | да |
| 6 | Продуктов | `productsCount` | Целое число | нет | нет |

### 4.2. Статусы

| Значение | Текст | Цвет тега |
|---|---|---|
| `LEAD` | Зарегистрирован | токен `status-neutral` |
| `ACCOUNT_OPENED` | Открыл счёт | токен `status-info` |
| `FUNDED` | Пополнил счёт | токен `status-success` |
| `INACTIVE` | Неактивен | токен `status-muted` |

Статус всегда передаётся текстом, цвет — дополнительный признак.

### 4.3. Отображение денежных сумм

- Источник — целое число копеек. Арифметика с суммами выполняется только в копейках, в целых числах.
- Форматирование через общую утилиту `formatMoney` из `shared/lib/money`.
- Формат: разделитель разрядов — неразрывный пробел, дробная часть — запятая, всегда два знака, символ `₽` через неразрывный пробел. Примеры: `1234567` → `12 345,67 ₽`, `0` → `0,00 ₽`, `5` → `0,05 ₽`.
- Выравнивание в колонке — по правому краю.

## 5. Фильтры и поиск

| Элемент | Поведение |
|---|---|
| Поиск по ФИО | Поле ввода с подписью «Поиск по ФИО». Запрос отправляется при длине от 2 символов после удаления пробелов по краям, через 300 мс после последнего изменения поля. При длине 0–1 символ параметр `q` не передаётся |
| Статус | Множественный выбор из статусов п. 4.2, подпись «Статус» |
| Период регистрации | Выбор диапазона дат, подпись «Период регистрации». Можно задать только начало или только конец. Границы — календарные даты, выбранные пользователем; они передаются в API как есть в формате `YYYY-MM-DD` без пересчёта часового пояса, сравнение выполняет бэкенд |
| Сбросить фильтры | Кнопка видна, если задан хотя бы один фильтр. Сбрасывает поиск, статус и период. Сортировку не сбрасывает |

Любое изменение фильтров или сортировки:
- загружает список с первой порции;
- прокручивает таблицу к началу.

## 6. Сортировка

- Сортировка серверная, по одной колонке.
- Клик по заголовку сортируемой колонки: если колонка не отсортирована — `desc`; если `desc` — `asc`; если `asc` — `desc`.
- Направление отображается иконкой в заголовке и атрибутом `aria-sort` (`ascending` / `descending`) у заголовка колонки.

## 7. Состояния

| Состояние | Условие | Отображение |
|---|---|---|
| Первичная загрузка | Нет данных, идёт запрос первой порции | Скелетон таблицы на 10 строк. Панель фильтров доступна |
| Загрузка следующей порции | Идёт запрос следующей порции | Индикатор под последней строкой с текстом «Загружаем ещё…» и ролью `status`. Загруженные строки остаются |
| Пусто, без фильтров | `total = 0`, фильтры не заданы | «У вас пока нет клиентов. Поделитесь реферальной ссылкой, чтобы пригласить первого» |
| Пусто, с фильтрами | `total = 0`, задан хотя бы один фильтр | «Ничего не найдено» и кнопка «Сбросить фильтры» |
| Ошибка первой порции | 5xx, сетевая ошибка или ответ не по схеме | «Не удалось загрузить клиентов» и кнопка «Повторить» |
| Ошибка следующей порции | То же при догрузке | Загруженные строки остаются. Под ними сообщение «Не удалось загрузить клиентов» и кнопка «Повторить», повторяющая только догрузку |
| Нет доступа | 403 | «Раздел недоступен. Обратитесь к персональному менеджеру» |

## 8. Загрузка данных и прокрутка

- Пагинация бесконечной прокруткой, порциями по 50 записей, по курсору.
- Следующая порция запрашивается, когда до конца загруженных строк остаётся 10 строк или меньше.
- Отрисовываются только видимые строки и запас не более 10 строк сверху и снизу (виртуализация).
- Высота строки фиксированная.

## 9. Навигация и восстановление состояния

### 9.1. Параметры адресной строки

Фильтры и сортировка хранятся в адресной строке:

| Параметр | Пример |
|---|---|
| `q` | `q=Иванов` |
| `status` | `status=LEAD,FUNDED` |
| `from`, `to` | `from=2026-01-01&to=2026-03-31` |
| `sort` | `sort=commissionKopecks:asc`. Не указывается, если сортировка по умолчанию |

Соответствие параметров адресной строки и API: `q` → `q`, `status` → `status`, `from` → `dateFrom`, `to` → `dateTo`, `sort` → `sort`.

- При открытии страницы по ссылке с параметрами фильтры и сортировка применяются из неё. Ссылкой можно поделиться.
- Некорректные значения параметров игнорируются, применяются значения по умолчанию.

### 9.2. Переход в карточку и возврат

- Клик по строке или `Enter` на строке в фокусе открывает карточку клиента `/clients/:clientId`.
- При возврате кнопкой «Назад» браузера или приложения:
  - восстанавливаются фильтры и сортировка;
  - загруженные ранее строки отображаются сразу, без повторного запроса, если данные получены не более 60 секунд назад. Иначе строки отображаются сразу и обновляются в фоне;
  - позиция прокрутки восстанавливается так, что строка, по которой был переход, видна на экране.
- При перезагрузке страницы восстанавливаются фильтры и сортировка. Позиция прокрутки после перезагрузки не восстанавливается.

## 10. Пользовательские настройки колонок

- Через кнопку «Настроить колонки» агент может скрывать и показывать колонки, кроме «ФИО».
- Настройки сохраняются между сессиями на этом устройстве, отдельно для каждого агента. Идентификатор текущего агента предоставляет сессия приложения.
- Настройки не попадают в адресную строку.
- Кнопка «По умолчанию» возвращает исходный набор видимых колонок.

## 11. Доступность

- Таблица имеет семантику таблицы, заголовки колонок связаны с ячейками.
- Строки доступны с клавиатуры: фокус по `Tab`, переход в карточку по `Enter`.
- У всех полей фильтров есть доступные подписи (п. 5).
- Статус не передаётся только цветом.

## 12. Критерии приёмки

| ID | Критерий |
|---|---|
| AC-01 | При открытии раздела отображается скелетон, затем первые 50 клиентов, отсортированные по дате регистрации по убыванию, и общее количество в заголовке |
| AC-02 | Колонки, их порядок, форматы и видимость по умолчанию соответствуют п. 4.1–4.2 |
| AC-03 | Комиссия отображается по правилам п. 4.3, включая значения `0` и `5` копеек |
| AC-04 | Поиск отправляет запрос только при длине от 2 символов и через 300 мс после последнего ввода: при посимвольном вводе «Иванов» отправляется ровно один запрос с `q=Иванов` |
| AC-05 | Фильтры по статусу и периоду передаются в запрос; кнопка «Сбросить фильтры» видна только при заданных фильтрах и не сбрасывает сортировку |
| AC-06 | Изменение фильтров или сортировки загружает первую порцию и прокручивает таблицу к началу |
| AC-07 | Сортировка переключается по п. 6, отображается иконкой и `aria-sort` |
| AC-08 | При прокрутке к концу подгружается следующая порция; загрузка прекращается при `nextCursor = null` |
| AC-09 | Отображаются все состояния п. 7; ошибка догрузки не удаляет загруженные строки, «Повторить» повторяет только догрузку |
| AC-10 | Фильтры и сортировка отражаются в адресной строке по п. 9.1 и применяются при открытии по ссылке; некорректные значения игнорируются |
| AC-11 | После перехода в карточку и возврата назад фильтры, сортировка и загруженные строки восстанавливаются без повторного запроса (в пределах 60 секунд), строка перехода видна на экране |
| AC-12 | После перезагрузки страницы восстанавливаются фильтры и сортировка |
| AC-13 | Настройки видимости колонок сохраняются между сессиями отдельно для каждого агента; «ФИО» скрыть нельзя; «По умолчанию» сбрасывает настройки |
| AC-14 | Строки доступны с клавиатуры, переход в карточку по `Enter`; у фильтров есть подписи; статус передаётся текстом |
| AC-15 | При 10 000 загруженных строк в DOM находится не более 60 строк таблицы |
