# Харнесс прогонов

Запускает оцениваемого агента (Claude Code, неинтерактивно, по подписке) на копии замороженной базы, проверяет защищённые файлы, прогоняет скрытую приёмку, снимает скриншоты и сохраняет результаты. Прогоны строго последовательные: порт 5173 зашит в защищённые конфиги базы, и параллельные агенты мешали бы друг другу.

## Подготовка

1. Токен подписки (один раз), вне репозитория:
   ```
   claude setup-token
   mkdir -p ~/.config/sdd-eval && pbpaste > ~/.config/sdd-eval/claude-oauth-token && chmod 600 ~/.config/sdd-eval/claude-oauth-token
   ```
   Путь можно переопределить через `SDD_EVAL_TOKEN_FILE`.
2. Порт 5173 должен быть свободен.

## Запуск

```
node eval/harness/run.mjs --round 1              # прогон №1 каждой конфигурации
node eval/harness/run.mjs --only H-full-on:2     # один прогон
node eval/harness/run.mjs --pilot H-full-on      # пилот → eval/results/_pilot/, в сводку не входит
node eval/harness/run.mjs --round 2 --dry-run    # что будет запущено
node eval/harness/summarize.mjs                  # eval/results/summary.{json,md}
node eval/harness/run.mjs --finish <папка логов>  # довести прогон, если харнесс упал после агента
node eval/harness/rescore.mjs <папка результатов> --reason "…"  # повторная приёмка по feature.diff
```

`--finish` берёт `state.json` из папки логов прогона и выполняет всё после агента; агент не перезапускается. `rescore.mjs` собирает копию базы, применяет `feature.diff` прогона и заново прогоняет приёмку; прежний результат сохраняется в `acceptanceHistory`. Нужен, если приёмочные тесты исправили после прогона.

Опции: `--time-limit 25m` (по умолчанию 25 минут), `--max-turns 300`, `--keep` (не удалять копию).

**Ограничитель окна.** Перед каждым прогоном харнесс читает `/usage`. Если окно + ожидаемый расход прогона (`WINDOW_GUARD` в `config.mjs`: Haiku 10, Sonnet 30 п.п.) больше 95%, он ждёт сброса окна + 2 минуты, затем проверяет снова. Если не хватает недельного лимита — останавливается с ошибкой. Ожидание можно прервать Ctrl+C: прогон ещё не начат, ничего не теряется.

Повторный запуск того же круга пропускает готовые прогоны (`complete`, `timeout`). Незавершённые и `infra_error` (например, исчерпан лимит подписки) переносятся в `eval/results/_aborted/` и запускаются заново.

## Конфигурации

| id | Модель | Спека | Контур проверок |
|---|---|---|---|
| H-brief-off | `claude-haiku-5-5` | краткая | нет |
| H-full-off | `claude-haiku-5-5` | полная | нет |
| H-brief-on | `claude-haiku-5-5` | краткая | да |
| H-full-on | `claude-haiku-5-5` | полная | да |
| S-full-off | `claude-sonnet-5-5` | полная | нет |
| S-brief-off | `claude-sonnet-5-5` | краткая | нет |

`S-brief-off` добавлена после круга 1: её прогон 1 — отдельно (`--only S-brief-off:1`) перед кругом 2.

Круг k начинается с k-й конфигурации, чтобы время суток не совпадало с конфигурацией. Стартовый промпт: «Реализуй SPEC.md, следуя CLAUDE.md». `--effort` не передаётся: используется значение CLI по умолчанию; CLI его не сообщает, в `result.json` записано документированное значение для модели.

## Один прогон

1. Копия базы `541a56f` в `$TMPDIR/sdd-eval-runs/`, спека как `SPEC.md`. Для «без контура» из `CLAUDE.md` вырезается блок между маркерами `contour`.
2. **«Без контура»:** `node_modules/.bin/{tsc,eslint,vitest,playwright}` в копии заменены заглушкой, а PreToolUse-хук отклоняет запуск проверок любым способом. Попытки считаются (`blockedCheckAttempts`). Перед приёмкой заглушки снимаются.
3. **Изоляция:**
   - чистый `CLAUDE_CONFIG_DIR` (рядом с копией, а не в запрещённой папке логов: туда CLI сохраняет длинный вывод инструментов) и OAuth-токен подписки, без API-ключа, без пользовательских настроек, памяти, skills и MCP;
   - запрет `Read`/`Edit`/`Write`/`Glob`/`Grep` и Bash-команд с путями репозитория стенда, копий эталона и логов;
   - копии эталона из `$TMPDIR/sdd-eval/` удаляются перед прогонами;
   - после прогона лог проверяется на следы этих путей (`isolation.leakSuspect`).
4. Агент работает до 25 минут, затем SIGTERM/SIGKILL группе процессов; оставленные dev-серверы добиваются.
5. Контрольные суммы защищённых файлов до и после. Нарушение = провал, AC считаются за 0, приёмка всё равно выполняется.
6. Приёмка `eval/acceptance/run.mjs`, скриншоты пяти состояний, `/usage` до и после — загрузка окна лимитов подписки. `/usage` читается обычным входом пользователя: токен `setup-token` даёт доступ только к вызовам модели. Окно общее для аккаунта, поэтому во время прогонов в других сессиях лучше не работать.
7. Токен ищется во всех логах и результатах и удаляется, если найден (`isolation.tokenFoundIn`).

## Результаты

`eval/results/<config>/<run>/` (в репозитории): `result.json`, `PLAN.md` агента, `feature.diff`, `queryClient.diff`, `acceptance.json`, `screens/*.png`, `screens.json`.

Логи — вне репозитория, `~/.local/share/sdd-eval/runs/<config>/<run>-<время>/`: `transcript.jsonl.gz` (полный stream-json), `stderr.log`, `harness.log`, `guard.log`, `blocked-bins.log`, настройки прогона. Путь записан в `result.json` → `artifacts.logsDir`.

## Стоимость

Условная стоимость = токены из лога × публичные цены API (`prices.json`, источник и дата там же). Считается по каждому запросу: у Haiku 5.5 тариф зависит от длины промпта, а промпт агента быстро переходит 100 тыс. токенов. Usage запроса берётся из `message_start` + `message_delta` (CLI запускается с `--include-partial-messages`): в событиях `assistant` `output_tokens` фиксируется в начале ответа и занижен. `tokens.usageCheck` сверяет сумму с итоговым `modelUsage` CLI, `tokens.incompleteRequests` — ответы без `message_delta` (оборваны таймаутом). Оценка `total_cost_usd` из CLI с публичными ценами не совпадает и хранится только как `cliCostUsd`.

`summarize.mjs` даёт две метрики:
- **стоимость принятого результата** = стоимость всех прогонов / прогоны с 15/15 без нарушения защиты;
- **стоимость одного выполненного AC** = стоимость всех прогонов / сумма выполненных AC.

Вторая определена, даже если принятых прогонов нет.
